# Phase 2.5 — real Sliver C2 (built + proven live)

Date: 2026-10-24. Branch `real-range`. Authorized live build (Dante) on the native-Intel
deploy host; everything inside the Docker range.

## What was built
A real [Sliver](https://github.com/BishopFox/sliver) v1.7.8 C2 server runs as a container
(`range-attacker_c2`) on red's infra network (`range_attacker`, `internal: true`). A foothold
installs a real Sliver implant that beacons to it; `swarm/beacon.py` queries the C2 for the new
agent (the Incalmo `check_new_agents` pattern, made real) as the spine's confirmation signal,
and the implant's beacon session is red's earned post-exploitation channel. The out-of-band
docker-exec marker remains the honest fallback when no C2 is present (and the Docker-free path).

- `ranges/sliver_c2/` — image build context: `build.sh` (downloads the pinned binaries,
  gitignored; the server bundles the offline implant-build toolchain), `Dockerfile` (unpacks
  assets at build so the container runs fully offline), `entrypoint.sh` (gRPC daemon + operator
  config + HTTP C2 listener), `run.sh <net> [ip]`.
- `swarm/beacon.py` — the real callback: `sliver_handle` (per-actor-ready; one shared C2 for
  v1), `c2_new_agents`/`parse_agents` (check_new_agents), `observe_beacon_sliver` (confirm by
  the agent's callback address/hostname — the C2's own record, never red's claim),
  `implant_execute` (earned channel: queue a beacon task, poll `tasks fetch`). `make_collector(r,
  c2=...)` uses the real callback when a handle is given, else the marker.
- `scripts/prove_sliver_c2.py` — the done-check: `--selftest` (Docker-free, same instrument with
  a faked beacon source) and `--live` (against the running C2 + beacon).

## Notes / honest scope
- The implant MUST be generated by the same C2 instance that serves the listener (CA match);
  a host-generated implant will not register. Implant generation needs `git` in the image
  (garble's linker patch) — baked in.
- The live implant delivery here is `docker cp` + exec onto the foothold (the implant + beacon
  are real); in-band delivery over red's RCE channel is the natural extension.
- A live Falco/Suricata rule firing on the beacon flow is the sensor standup; the flow itself is
  real and C2-recorded. `--selftest` exercises the identical instrument with a faked beacon
  source, so `make test` covers the wiring Docker-free.
- Carries into Phase 4 (one effect path): `beacon.py`'s `subprocess`/`docker` calls and
  `exploit_weblogic`'s `docker exec` are effect sites the one-effect-path grep must route.
